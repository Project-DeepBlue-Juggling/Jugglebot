## What

The report layout the checker pins grows from eight sections to nine: `## Items the Night
Shift could resolve with a small amount of input from you` sits directly after `## Questions
for the Operator`. Its body is generated by `python -m mapkit night inputs` (new
`mapkit/night_inputs.py`) from every open Item whose `night_skip` starts with `input-`, never
written by the model. `## Skipped` now lists only Items skipped tonight and ends with one
`unchanged: <n> Items not re-examined (reasons on each Item: night_skip)` line, which the
checker allows only as Skipped's last line.

Why: the owner asked for a standing list of what a little input from them would unblock, and
for the end of the nightly wall of unchanged Skipped rows.

- Cutover: `INPUTS_CUTOVER = "2026-11-15"` in `mapkit/night_shift_report.py`. Earlier dates
  pass as eight-section reports (and may carry the ninth); from the cutover nine are required.
  Every committed report is dated earlier and still passes.
- The new section is deliberately not in `ITEM_ROW_SECTIONS`: a standing list would otherwise
  mark every input Item as walked tonight in the preflight's carry rule (pinned by a test).
- A `|` in a title or note renders as `/` (the checker splits on every `|`).
- A nine-section report's Questions section ends with exactly one `earlier: <n> open questions from earlier nights, not re-listed` line (allowed only there, not an Item row).
- The stub report writes the section as `none recorded`.
- `tools/night_shift.sh`'s `append_*` helpers append to the end of the file and edit the
  Summary line, so nine sections and the trailer change nothing there. The map app's
  `report_counts` counts only Merged, Held and Questions; unaffected.
