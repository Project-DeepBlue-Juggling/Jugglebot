## Discussion

Written before the Fix. Triggers (b) and (c) hold: tradeoffs were accepted and the chosen approach beat reasonable alternatives for reasons the code does not show.

1. **One commit, not a staged flip.** The failure a staged flip causes: between a partial flip and its completion every old ID in the tree is unresolvable or wrong, and the auto-pull timer fast-forwards `main` into three clones every two minutes, so a half-flipped tree is published within minutes. A crosswalk file that exists switches `ids.per_kind()` and the allocator in every clone that pulls it, so the switch cannot lag the text it explains. One commit also means one `git revert`, which takes the crosswalk with it so the allocator falls back to the old form by itself. The cost is a 696-file diff nobody can read, which is why the proofs (T-R2 to T-R6) exist: the diff is verified by machine against its own inverse.
2. **`.hex` as the image identity, not `.elf`.** The plan's T-R4 said "image hash". The `.elf` differs between two clean builds of the same source (the first rebuild showed it), so an `.elf` comparison would fail without any ID reaching the binary and would teach everyone to wave off a T-R4 failure, which is the habit the proof must not breed. The `.hex` is the file that is flashed, so it is the image in the only sense that matters, and it is reproducible. The backstop is a source-level check: no `__DATE__`/`__TIME__`/`__FILE__`/`__LINE__` and no change in line count, so no line-anchored value moved either.
3. **Fixtures converted by hand, legacy tests kept and marked, not a mechanical renumber.** A fixture ID in a synthetic-repo test asserts parser behaviour (padding, kind prefix, a number shared across kinds). A mechanical map through the crosswalk would turn a test of the old form into a test of nothing, and could weaken an assertion without any failing test (the audit found one such weakening, B4, in a `not in` check that a rename had narrowed). Unit 2 therefore converted every test that models the live tree to per-kind IDs, kept 28 tests that are about the old form in their old form with `# legacy form: retired at P5` on the def, and recorded the residue line by line (it matches `grep -n JB` for all seven files). Cost: a test file carries both forms until P5.
4. **D-3: resolve on read, refuse on write, with a `getattr` guard in the fork.** An old ID in a bookmark, a commit message or a phone link is one lookup away from the right Item, so a read translates and prints the new ID. A write must not: a stale `JB-64` pasted into `set-status` would change an Item the typist no longer identifies correctly once the number has been reused by another kind, so a write refuses and names the new ID. The fork imports mapkit from a path that can be rolled back to a version without `legacy()`; `getattr(ids, "legacy", None)` makes that case behave as today (404) instead of crashing the app. A bad crosswalk file in the fork is also treated as no crosswalk. In mapkit itself a malformed csv still raises (audit B3), accepted because the file is frozen and committed.
5. **The proofs as committed scripts, not a paragraph.** `tools/probes/id_cutover/` holds T-R2, T-R3, T-R5, T-R6 and a `run_all.sh`, with evidence under `temp/probes/id_cutover/`. A paragraph claiming "I checked" cannot be re-run by the next session, and the P5 guard test reuses the same classifier; scripts can be re-run on any held branch after the sweep. The scripts are themselves frozen by the sweeper (rule `cutover-self`) because their patterns contain old-form text. The audit tested each script by planting a fault in its own domain; that test found one real hole in T-R2 (below).
6. **The two held fork branches and the four merged `night-shift/*` branches.** The held branches descend from an app version that already reads per-kind IDs, so the rollback root cause in precondition 5 (a held app branch older than P2 cannot read the new IDs) does not apply; the owner merges or drops them at the debrief. The four merged branches (the old-form names for Items 163, 169, 175, 190) are not renamed: they are merged, dead and awaiting the owner's deletion, and the sweep rewrote their names in prose to the Item's new ID per the plan's design. The audit's observation stands that prose and refs disagree until they are deleted, which is harmless because `night_shift_candidate.sh` is dual-form.
7. **Audit findings that changed the work.** The audit (opus, one pass, `temp/id-migration/p4-audit-report.md`) found 0 blocking. It restored narrative text where the sweeper had put a current holder's ID on a historical or synthetic number: a map-app test's fixture IDs (N1), the "one bug filed four times" duplicate range whose numbers were later reused by other kinds (N2), a 62-ID expansion in an INDEX row (N3), and a doubled bracket in a placeholder (N4). It found T-R2 exempting all of `mapkit/` (a planted `0.61` to `0.62` in `similar.py` passed), now exempt by name only. It also found two sweeper rule bugs, below.
